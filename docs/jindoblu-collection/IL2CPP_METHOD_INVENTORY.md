# JindoBlu IL2CPP Metadata: Controller Method Inventory

**Status:** recovered type and method names from the APK's Unity IL2CPP global metadata. This is deeper than printable-string scanning, but it is still metadata inspection—not decompiled native method bodies. Method names indicate likely responsibilities, not exact formulas or rules.

## How this was recovered

- Input: `assets/bin/Data/Managed/Metadata/global-metadata.dat` from the uploaded `base.apk`.
- Metadata magic: `0xFAB11BAF`; metadata version: `31`.
- Parsed the metadata string table, 88-byte type-definition records and 36-byte method-definition records to associate declared method names with types.
- Native implementation is in the ARM64 `libil2cpp.so`; no native decompiler was available in the sandbox. No application code was executed.

## Recommended next action

The strongest new implementation target is **Pool**, because the method inventory shows an explicit 2/3/4-player setup, cue-ball drag/release, pocket handling, score updates and CPU targeting. However, do not implement it as a claimed faithful port yet: first obtain native method bodies or conduct controlled reference play to measure shot physics and rules. **SoccerStars** is the next candidate with clear turn/goal methods. Existing direct/near matches should be audited before duplicates are added.

## Hard limitation

Method names are identifiers only. They do not recover native machine-code behavior, numeric constants, field values, animation timings, asset layouts or runtime scene state. Exact mechanics remain unverified. Official REA/JADX installation remains blocked by sandbox DNS/network failure; no method body was decompiled.
